---
title: "Idempotent Consumer"
description: "A consumer that receives a message twice produces the same result as receiving it once."
tags: [rabbitmq, messaging]
type: note
region: Messaging Region
lang: en
---

An **idempotent consumer** records the event ID in a "processed" table (primary key: event ID plus consumer name) **in the same transaction** as the business work; when it sees an old ID again it skips the work and still acks. Recording in a separate transaction means a crash midway loses or duplicates work. The event ID must be generated by whoever creates the event. See also [[en/concepts/idempotency|Idempotency]].
